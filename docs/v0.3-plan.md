# mast-web v0.3.0 plan

**Status:** draft, 2026-07-20 (evening, post-v0.2.0 tag). Sequenced roadmap for the "comprehensive" v0.3.0 shape — pays down all remaining v0.2.0 deferrals, delivers on multi-daemon as the marquee feature-parity item, extends the renderer dispatch to a real registry, adds automated end-to-end regression coverage, and lands a couple of polish items. Companion to [`web-design.md`](./web-design.md) (the architecture, evergreen). Rots when v0.3.0 tags out.

## Goal

Ship **mast-web v0.3.0** with:

1. **Foundational debt paid** — `state/` subscribe-pattern refactor extracts observable state from `app.js`. Deferred through PRs 1/2/4 of v0.2.0; the seam has been earning interest ever since. Unblocks a bunch of downstream work (observer-mode footer stamping in particular) that has been fighting the current activeTurn/runPrompt coupling.
2. **Full multi-daemon peer fan-out** — the real form of what PR 3's `/attach <url>` shipped as a minimum-viable slash. `GET /peers` on the primary daemon; per-daemon `AttachClient` instances; sidebar shows sessions across all daemons with per-daemon badges; cross-daemon session switching without a full page reload.
3. **Full observer-mode support** — banner shipped in PR 4b; footer stamping (StampLatestAssistantFooter equivalent for `turn-complete + usage-update.last_turn` when no `activeTurn`) is the invisible-but-important half. Requires the state/ refactor to accept externally-driven turns cleanly.
4. **Schema-driven slash-response renderer registry** — the substantive follow-through on PR 4a's dispatch skeleton. Table / tree / (v0.3.1+) chart primitives; client-side `_schema` validation; extension seam for custom renderers.
5. **Real batch runner** — currently stubbed with `ttfbMs: 50` hardcoded and a "phase B wires real backend" message. Wire to real `/inject` calls with streaming updates.
6. **Playwright automated smoke** — build on the mock backend from PR #18. Automated regression coverage beyond unit tests.
7. **Polish** — theme picker (cogo-wasm2 had one; nice re-add) + keyboard shortcuts (Ctrl+K for session picker, `/` for command palette, Ctrl+Enter for send, Esc for modal-close).

Non-goals for v0.3.0:

- **AG-UI protocol client.** Mast plans to speak AG-UI as a second wire (`mast/docs/ag-ui-design.md`); a client is a whole new subsystem, not a feature. Deferred to v0.4.0 or a dedicated design-first cycle.
- ~~**`/reset-ceiling` UX** — still blocked on [core-agent#331](https://github.com/go-steer/core-agent/issues/331) design. Nothing to build client-side until reset semantics are speced.~~ Shipped server-side as `GET/POST /sessions/{sid}/guardrails[/reset]` (core-agent#670/#671); client-side `/guardrails [reset]` landed 2026-08-14, outside this plan's PR sequence (post-v0.3.0 sync pass).
- **Model-switch endpoint + `/model` slash** — server-side POST /sessions/{sid}/model doesn't exist; needs a design pass + SwitchModelProvider capability interface. Deferred until upstream produces it.
- **Fixture-migration to a shared repo** — deferred per v0.2.0 §Q6 revision; revisit only if drift bites.

## Design overview

### The `state/` layer

Today's shape:

```
web/
├── attach-core/          # wire — done in v0.2.0
├── slash-render.js       # dispatch skeleton — done in v0.2.0
└── app.js                # everything else: state + rendering + input
```

v0.3.0 target:

```
web/
├── attach-core/          # wire (unchanged)
├── state/                # NEW: observable state model
│   ├── session.js        # per-session state (usage, tools, agents, capabilities)
│   ├── connection.js     # connection state machine
│   ├── daemons.js        # multi-daemon aggregation
│   └── subscriptions.js  # pub/sub primitives
├── slash-render.js       # renderer registry (extended)
└── app.js                # rendering + interaction (subscribers, no state)
```

Rules:

- `state/*` never touches the DOM. Emits change events; app.js subscribes.
- Reducers over typed events (from attach-core); no direct DOM side effects.
- Every reader is a subscriber — no `latest.X` lookups at render time; state changes drive renders, not the other way around.

**Why now:** the observer-mode footer stamping requires the turn dispatch to stamp state from events that aren't part of an `activeTurn` — impossible with the current `runPrompt`-owned dispatch model without a mini-refactor that would look a lot like state/. Same friction hits multi-daemon aggregation (per-daemon state that needs a common projection). Doing state/ first turns those into wiring, not architecture.

### Multi-daemon: per-daemon clients + peer discovery

Today: single `AttachClient` instance. Cross-daemon `/attach <url>` re-points the instance at a new endpoint (loses the outgoing daemon).

v0.3.0: registry of `AttachClient` instances keyed by endpoint URL. Sidebar aggregates sessions from all. Backend discovery via `GET /peers` on any connected daemon. State layer projects the union.

**Backwards-compat:** the single-daemon flow stays the default. Multi-daemon is an operator gesture (add via UI or `/attach`), not automatic.

### Renderer registry

Today: `SlashRender.renderSlashResponse(response)` dispatches on `_render` → one of `{text, markdown, json}`.

v0.3.0: registry pattern.

```js
SlashRender.register('table', {
  detect: (r) => r._render === 'table',
  render: (r) => ...,
  schema: {...}, // optional; used for _schema validation
});
```

Built-in renderers grow from 3 to 5:
- `text`, `markdown`, `json` (existing)
- `table` — rows/columns per schema
- `tree` — nested data

Chart / graph renderers stay out of scope (v0.3.1 or beyond; they benefit from a small charting library which is a whole other decision).

### Playwright smoke

Layer on top of `dev/tools/mock-backend`. Playwright drives:
- Boot mock + dev server
- Load SPA in headless chromium
- Feed each conformance fixture as a scenario
- Assert DOM state matches expected (session in sidebar, streaming rendered, tool-call chip present, etc.)

Runs in CI as a separate `smoke.yml` workflow (not blocking normal PRs; runs on `main` push + tag).

## Roadmap

Seven PRs. Each sized to be reviewable independently; every PR after PR 1 assumes state/ has landed.

| PR | Scope | Blocks on |
|---|---|---|
| **PR 1 — state/ subscribe-pattern refactor** | Extract observable state model from app.js. Behavior-preserving. | — |
| **PR 2 — Full multi-daemon peer fan-out** | Per-daemon AttachClient registry + `GET /peers` + sidebar aggregation + Add-daemon dialog. | PR 1 |
| **PR 3 — Full observer-mode footer stamping** | Turn dispatch accepts externally-driven turns; StampLatestAssistantFooter equivalent. | PR 1 |
| **PR 4 — Renderer registry + table/tree** | Extend slash-render.js from dispatch to registry; add table + tree built-ins; `_schema` validation. | — (independent of state/) |
| **PR 5 — Batch runner real backend** | Wire batch to real `/inject`; streaming table updates. | PR 1 |
| **PR 6 — Playwright automated smoke** | Playwright setup + fixture-driven scenarios + `smoke.yml` workflow. | — |
| **PR 7 — Polish: theme picker + keyboard shortcuts** | Theme picker (cogo-wasm2 re-port); Ctrl+K / `/` / Ctrl+Enter / Esc bindings. | — |

Sensible order to ship:
1. PR 1 (foundation)
2. PR 4 or PR 6 in parallel (independent of state/)
3. PR 2 + PR 3 (both need state/)
4. PR 5 (needs state/ + some batch-panel state)
5. PR 7 last (touches app.js broadly; least conflict if it goes on top)

Weeks 1-6 approximate; each PR is 3-5 days of focused work.
