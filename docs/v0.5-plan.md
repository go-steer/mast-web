# mast-web v0.5.0 plan

**Status:** draft, 2026-09-17. Supersedes [`v0.4-plan.md`](./v0.4-plan.md) (executed, v0.4.0 tagged 2026-09-15).

## Goal

v0.4 was a removal release: it retired the classic console, collapsed three presentations to two, and unified the state seam. v0.5 is the opposite motion, and it has a forcing function.

**mast-web consumes attach protocol 1.7.0. core-agent is on 1.12.0.** Five minor versions, and they are not all additive in effect: **1.11.0 removed the implicit resume that was the only way mast-web could ever clear a hold.** A session parked by anyone other than this client — another operator, core-tui's `/pause`, an alert-driven watcher — is now a dead end in the browser. The operator types, the message queues behind the gate, and nothing happens.

The second thing that changed while v0.4 was in flight: **1.10.0 added `GET`/`PATCH /sessions/{sid}/acl`.** v0.4's §5 shipped ownership as a *derived, read-only* label, and the v0.4 plan recorded the reason — "core-agent ACL mutation — no route today. Needed if session sharing ever becomes a product feature." That sentence is now false. The route exists, and the surface that needs it is already built.

So v0.5 is: **catch up to the protocol, and make the multi-user surface actually multi-user.** Close the hold dead-end, ship sharing, and land the rest of the drift.

Hosting — [#86](https://github.com/go-steer/mast-web/issues/86) (oidc), [#66](https://github.com/go-steer/mast-web/issues/66) (Kind against a real backend), [#6](https://github.com/go-steer/mast-web/issues/6) (hosted SPA) — is a coherent release of its own and is deliberately v0.6. See §6.

## Design overview

### 1. The drift, item by item

Everything below is from `core-agent/pkg/attach/events.go:76-250`, which carries the per-version rationale, and the handlers it points at. The column that matters is the last one: most of this is free, and a few items are not.

| Version | Change | What it costs us |
|---|---|---|
| **1.8.0** (#816) | `canceled` in the turn-error `kind` enum, `retryable: false` | **Nothing.** We never read `retryable` — a grep over `web/` finds no reference. The bump exists to stop a client offering "retry?" after a deliberate interrupt; we never offered one. Worth recording as checked rather than assumed, because it *is* a behaviour change and the obvious reading is that it costs something. |
| **1.9.0** (#768) | `GET /sessions/{sid}/subagents` rows carry optional `tools` | Small. `/specialists` gains the grant per subagent. Note the trap the upstream comment spells out: a 1.9.0 daemon also omits the key for a subagent with no grant, so **absence cannot be read as "this specialist has nothing"** — it falls back to the roster without a grant. |
| **1.10.0** (#797) | `GET` + `PATCH /sessions/{sid}/acl`; `viewers`/`contributors` on `POST /sessions` | The release. §3. |
| **1.10.0** (#830) | `by` on perms history rows, `approver` on the respond 200 | Small, and it is the first identity to flow *back out* per-decision. §5 of the v0.4 plan flagged this as a precedent worth citing for the per-turn attribution ask. Both fields are omitted when the daemon verified no identity, so "who approved this" renders as unknown, never as assumed. |
| **1.10.0** (#808) | `POST /sessions/{sid}/title` | §4. |
| **1.10.0** (#698) | `POST /inject` takes optional `wake` | We always want the historical behaviour (`wake` omitted/true) — an operator typing into a box means it now. Worth *not* wiring a control for; recorded so nobody adds one speculatively. |
| **1.10.0** (#840) | `POST /inject` and `/wake` report `prompt_id` | The only handle a client has on the turn its message lands in, from the moment it sends. We have no correlation need today, but the batch runner is the one surface that will. Capture it in the store; don't build on it yet. |
| **1.11.0** (#878) | **`POST /inject` no longer releases a pause hold** | §2. This is the one. |
| **1.12.0** (#896) | `state: "running"` finally reachable on `GET /status`; `turn_in_flight` beside it | Real accuracy win for `status-bar.js`. The state was declared from the start and never produced — a mid-turn `/status` answered `"idle"`. Note `turn_in_flight` is separate from `state` because **pause outranks running**: a session parked mid-turn still reports `"paused"` so hold banners keep working, and the bool is how you learn the interrupted turn is still executing. §2 needs exactly that distinction. |
| **1.12.0** (#897) | Subagent stop reports `stopped` and `status` honestly | Small. `stopped: false` now means "it had already finished", where through 1.11.0 both cases said `true` and an operator stopping a subagent that completed thirty seconds earlier was told they'd stopped it. |

Two of these are behaviour changes inside a minor bump (1.11.0 and 1.12.0's `stopped` value), which upstream documents at length precisely because the additive-minor convention would otherwise imply they aren't. Read those two comments before touching either.

### 2. The hold is a dead end, and that is what forces #70

The mechanism, end to end:

**Our own Stop is safe.** `client.interrupt()` sends `{"hold": false}` deliberately — `web/attach-core/client.js`, in the long comment above `interrupt()`. v1.5.0 flipped this endpoint's default from "cancel the turn" to "park the loop" (`hold := req.Hold == nil || *req.Hold`), so an empty body parks. We ask for the old semantics explicitly, which is what the spec's §4 preserved that flag for. Nothing in v0.5 changes this; [#73](https://github.com/go-steer/mast-web/issues/73) is what makes Stop correct.

**Everything else is not.** The gate can be closed by a route we don't call: `POST /pause`, another operator's core-tui `/pause`, an interrupt from a different client that didn't pass `hold: false`. `state/session.js` models all of it — `pause.paused`, `since`, `reason`, `interrupted`, `resumeMode`, fed by both `applyPauseEvent` and `applyPauseStatus` with a settle window between them. We *see* the hold perfectly.

**And we cannot clear it.** `web/attach-core/client.js` has `inject()`, `wake()` and `interrupt()`. There is **no `resume()`**. Through 1.10.0 that was survivable by accident: an inject from any caller but auto-continue called Resume for you. 1.11.0 removed the shim, and the upstream rationale is worth quoting because it also tells us what *not* to build:

> That shim assumed a human at the other end of the socket. It cannot check: callers carry an identity, not a species, and a machine producer can legitimately inject under a person's identity.

So the fix is not to restore the implicit behaviour on our side. It is the endpoint that was added for it: `POST /sessions/{sid}/resume` with `{"mode": "steer"|"continue"|"abandon"}`, `steer` required and non-empty when `mode` is `steer`, 501 when the agent implements no `PauseController` (`core-agent/pkg/attach/handlers_pause.go`).

Three things already in place, which is why this is a port and not a design:

- **The capability gate exists and is unused.** `client.supportsPause()` is already written, already distinguished from `emitsPauseEvents()` — "a v1.5.0 server lists the `pause` event whether or not the agent behind it implements PauseController, so the event being declared is not permission to draw a button" — with the comment "(The controls themselves are #70.)" Render on `emitsPauseEvents()`, gate controls on `supportsPause()`.
- **The mock already serves both routes.** `cmd/mast-web-server/mock_pause.go:260,299`.
- **core-tui shipped the vocabulary.** `tui/slash_builtin.go:878` — `/continue`, `/cont` "release a hold and carry on"; `/abandon` "release a hold and drop the held work". It deliberately does **not** call it `/resume`: "`resume` belongs to the pause API, where `/continue` and `/abandon` …". Take the same names. Two shells and a TUI disagreeing about the word for this is the kind of thing that never gets fixed later.

Scope for the PR: a banner when `pause.paused` (it is window-level state as much as panel-level — `status-bar.js` owns the window half), the three commands through the existing `BUILTINS` table so `/help` and the palette get them free, and a steer path. `turn_in_flight` from 1.12.0 is what lets the banner say "held, and the interrupted turn is still running" rather than guessing.

### 3. Sharing

v0.4 §5 derived "mine vs shared" from `user === caller`, and was careful about why it derived rather than read: the wire does not carry the owner, and inventing an `owner` field on a session row would have been [#41](https://github.com/go-steer/mast-web/issues/41) in reverse. **None of that changes.** The ACL is a *separate resource* with its own endpoint, which is exactly the shape that reasoning asked for.

The contract, from `core-agent/pkg/attach/handlers_acl.go`:

- `GET /sessions/{sid}/acl` → `{owner, viewers, contributors}`. Both lists are **never omitted**, `[]` rather than `null` — "a client that had to treat a missing key and an empty list alike would be back to guessing."
- `PATCH` with `{viewers?, contributors?}`. The fields are `*[]string` upstream so **absent means leave alone and `[]` means clear**. A UI that round-trips the whole object on every edit is fine; one that sends only the list it touched must mean it. Sending `owner` at all is refused with a reason rather than ignored — transfer is not this endpoint's job.
- **Both verbs are `ActionSessionAdmin`** — owner or admin. The read is gated as hard as the write on purpose: "the ACL names the other people who can see an incident, and a Contributor being able to enumerate their co-responders is a disclosure the matrix doesn't otherwise grant."
- **Denial is 404, not 403** (`authorize`'s standing convention — a denial reads as "that session is gone"). So a client **cannot probe** to feature-detect; it must read the negotiated protocol version. A pre-1.10.0 daemon answers the same 404.

Three consequences for the UI, all load-bearing:

1. **The share gesture appears only on sessions you own.** Not as a courtesy — a non-owner literally cannot read the ACL to populate the dialog, and the failure is indistinguishable from a deleted session.
2. **Feature-detect on the version, never on a 404.** This is the first place we need the negotiated version as a *decision* input rather than a display string.
3. **Viewers and contributors are different words and must stay different in the UI.** Contributors is what unblocks the escalation case upstream describes — a watcher opens a session, pages a human, and the human's reply arrives under their own identity. "Share" as one undifferentiated verb would collapse that.

`POST /sessions` also gained the optional body, so a session can be created shared. Second-order; the sidebar gesture is the release.

The mock needs the other half: `mock_acl.go` already keeps the ACL in a side table (deliberately, per v0.4 §5), so this is adding two routes over a structure that exists, plus `smoke/019-multi-user.spec.js` growing the case it was built for — bob sees a session after alice shares it.

### 4. Rename

`POST /sessions/{sid}/title`, the manual override for the titles 1.6.0 started inferring and `state/daemons.js` already reads. Small and visible. Three details in the contract that a naive implementation gets wrong:

- The `title` key is **required**; `""` clears and re-arms automatic generation, an **omitted** key is a 400. So "clear the title" and "don't change the title" must be different code paths.
- The 200 answers with what was stored **after the host's normalization** — render that, not the string we sent.
- The `persisted` flag is **not** success. `false` is the norm for a daemon with no ACL store. Reading it as a failed rename would show an error on the common path.
- A host with no title capability answers **501**, which — unlike the 404 an unauthorized caller gets — is safe to feature-detect on, since reaching it means the caller was already authorized.

### 5. What the mock owes

The mock declares `wireProtocolVersion = "1.7.0"` (`cmd/mast-web-server/mock.go:45`). Every item above needs its fixture side, and v0.4's PR 0 established the discipline: **bring the mock up to the version it claims, in the same PR that claims it.** `TestMock_SessionRowsUseCanonicalWireShape` is the pattern — a test that fails when the mock invents a shape the real wire doesn't have.

The 1.11.0 item is the one to get right in the mock, because it is the only way the dead end is testable: the mock's inject must **stop** releasing the gate, and a smoke spec should assert that a held session stays held through a typed message and opens on `/continue`.

### 6. What v0.5 is deliberately not

- **Hosting.** #86 (oidc — unblocked by purser v0.1.0, not blocked), #66 (Kind vs. a real core-agent), #6 (hosted SPA). These three are one coherent story about someone other than us running this, they share no files with the above, and splitting them out keeps both releases legible. **v0.6.**
- **[#43](https://github.com/go-steer/mast-web/issues/43) autocomplete.** Still unblocked, still small, still not part of either thread. It rides along in whichever release has room.
- **Per-turn caller attribution.** Still the one protocol ask (`shells-design.md` §9). 1.10.0's `by` is per-decision, not per-turn. Unchanged — but now with a precedent to cite.
- **The framework decision** (`web-design.md` OQ 3, deferred twice). v0.4 removed ~4,400 lines; the honest re-evaluation is against the post-retirement number. v0.5 *adds* surface, so this is the wrong release to judge it in either. Deferred a third time, explicitly.
- **Owner transfer.** The endpoint refuses it by design. Not ours to invent.

| **PR 5 — attribution + subagent honesty** | `by`/`approver` in the perms surface; subagent `tools` in `/specialists` (absence ≠ no grant); `stopped`/`status` on subagent stop. Three small independent reads. | PR 0 |
| **PR 6 — docs reconciliation** | `web-design.md` protocol refs 1.7.0 → 1.12.0; mark `v0.4-plan.md` and `upstream-drift-2026-09-12.md` executed; CHANGELOG `## [0.5.0]`. | PRs 1-5 |

Sensible order to ship:

1. PR 0 — nothing else is testable without the mock at 1.12.0.
2. PR 1 — the dead end is the reason this release exists; ship it first of the visible work.
3. PR 2, then PR 3 (both sidebar gestures; 3 is much smaller and can slip).
4. PR 4 and PR 5 in parallel from the start — neither touches a gesture.
5. PR 6 last, when there is something true to write.

The discipline to keep from v0.4: PR 0 is a *wire* PR, reviewed as one. Landing a capability and its UI together is how a contract detail like "`persisted` is not success" gets buried under a dialog nobody re-reads.

## Open questions

1. ~~**Does the share dialog live in the sidebar or the palette?**~~ **Resolved 2026-09-17: the palette**, as `/share`, and not on taste. The ACL routes are session-scoped, but `state/daemons.js` holds one `AttachClient` per *daemon*, so a sidebar row has no bound session to ask about. Worse, `X-Attach-Protocol-Version` is stamped only on `/events` (`pkg/attach/protocol.go:95`, sole caller `handlers.go:478`), so a row for a session nobody has opened has never seen a version — and §3 forbids probing, because denial on these routes is 404 and a probe cannot tell "too old" from "not yours". A panel has both facts. The ownership rule then falls out for free: with the version already known, a 404 has exactly one meaning left, and that is what the message says.
2. ~~**Does the hold banner belong to the panel or the window?**~~ **Resolved 2026-09-17: both**, as suspected — the banner in the panel (the hold is the session's), a held count in the status bar (the window's answer to "is anything waiting on me"). Shipped in #70.
3. **Do we surface `prompt_id` at all in v0.5?** Captured in the store by PR 0 either way. The batch runner is the only surface with a correlation problem, and it doesn't have one yet.
4. ~~**Is #70 deferrable?**~~ **Resolved 2026-09-17: no.** See §2.

## Rot condition

Mark this doc **executed** when v0.5.0 is tagged and all 7 PRs are merged or explicitly deferred with a follow-up issue linked.

**Mark, don't delete** — correcting the instruction v0.2, v0.3 and v0.4's plans all carried and none of them followed. Three plan docs outlived a "delete this doc when" clause, `web-bootstrap.md` set the actual convention with a `**Status:** executed` header, and by now other files link inward (`shells-design.md` → `v0.3-plan.md`, `client.js` → `v0.3-plan.md`, `CHANGELOG.md` → `v0.4-plan.md`). A rot condition that has never once been executed is not a rot condition; it is a note that the doc is finished, and it should say so.

If the protocol has drifted again by the time v0.5 tags, that is not a reason to extend this plan. Record the new high-water mark here and let v0.6 carry it — the failure mode this release is repairing is five versions of silent drift, and the repair is not a bigger catch-up PR but a shorter interval between them.
